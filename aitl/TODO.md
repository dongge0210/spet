## 检测器盲区（2026-10-10，TCMT 会话实测）

一段 129 字符的中文，检测器给 0/100「人类」，但那段里确实有一个机器手势：用 `——`
引出文件路径（`设计稿 —— AvaloniaUI/designs/...`）。没抓到的原因有三条。

### 1. 短样本下 per_1k 误导

`em_dash_per_1k` 在这个长度上算出 7.75（1 个破折号 / 129 字符），看着像超标，绝对值只有 1。
打分本身走绝对阈值（`scripts/detect.py:146`，`em_dash <= 2` 不扣分），短样本侥幸过关，
但 JSON 里那个 `per_1k` 字段会把看的人带偏。

改法：加最小样本门限（比如 <200 字符不输出 per_1k），或在该字段旁标注样本过短。

### 2. 只数个数，不认用法

`scripts/detect.py:106-107` 的 `em_dash = text.count("——") + ...` 分不出两种破折号：

- `——` 后面紧跟反引号 / 路径 / 英文标识符 → 引出内容，是 AI 手势，高频惯用
- `——` 做正常停顿 → 人类照写

改法：加正则区分。后者照旧计数，前者单独计数并加权，它才是特征本身。

### 3. 跨轮次习惯看不见

单篇检测抓不到「每轮回复都来一个破折号」这种节奏。这是固有边界，但 SKILL.md 可以写明：
多轮对话场景，把连续几轮的输出拼起来再跑。

### 附带观察

模型写中文技术回复时，「`——` 引出路径/解释」是高频手势。检测器若能单独拎出这一条报，
比总分更有用。

## AI「一堆废话」：某些场景下填充暴涨（2026-10-14）

用户观察:AI 在**某些情况下**会输出一大段废话——句子多、信息少、翻来覆去。当前
`detect.py` 对这一维**完全无感**:

- 已实现的信号(phrase_hits / em_dash / emoji / triad…)全是**特征词计数**;
  而废话的典型形态恰恰是**一个特征词都没有的啰嗦**——把一句话拆成五句、换着说法重复、
  复述提问、绕完一圈回到原点。
- `sentence_cv` 只在 ≥4 句时算,而且只测句长**方差**,不测**信息密度**。

可能判据(待验证,还没有真样本定阈值):

1. **信息密度代理**:每句的实词/数字/专名数,或全篇 MATTR(unique-token ratio)。
   长文里 MATTR 低 + 句数多 = 稀释。
2. **复述比**:与用户提问(或前文)的 n-gram 重叠率高 → 在原地绕圈。
3. **空转句占比**:一段里不含任何新增信息的过渡句比例。

**下一步**:需要 1–2 个**真实例子**才能定阈值/正则。下次遇到时把原文存进 `samples/`
(第一行写 `# expect:`,先写个占位的 `# expect: 人类` 也行),再回来标。
